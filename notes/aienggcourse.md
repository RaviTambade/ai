## 4. One Architecture That Connects Everything

**Mentor**: Students, let's look at the bigger picture. Suppose we want to develop an intelligent Student Learning Assistant for Transflower.

A student asks: "Which skills should I improve to become employable?" How will our AI application answer? We need more than an LLM. We need an engineered system.

```

                    |
          +---------+---------+
          |         |         |

         LLM       RAG       MCP
          |         |         |
          |         v         v

          +---------+---------+
                    |

                    |

                    |
```

Let's understand the engineering responsibilities:

- **Python**: Implements application logic.
- **FastAPI**: Exposes backend services.
- **LLM**: Understands and generates responses.
- **RAG**: Supplies relevant learning knowledge.
- **MCP**: Connects AI with external business tools.
- **LangGraph**: Controls multi-step workflows.
- **Evaluation**: Measures response quality.
- **LLMOps**: Monitors reliability, latency and cost.

This is how individual technologies become an enterprise AI application.

## 5. The Most Important Engineering Lesson

**Mentor**: I want you to remember five principles.

1. Learn Programming Before Frameworks.  **Frameworks change. Programming fundamentals remain.**

2. Understand Data Before RAG. **RAG is not magic. It is an information retrieval engineering problem.**

3. Understand APIs Before MCP. **MCP connects AI applications with tools. Understanding APIs helps you design those integrations correctly.**

4. Understand Workflows Before Agents. **Not every problem needs an autonomous agent. Predictable workflows are often better.**

5. Understand Testing Before Production. **An AI application that works once is a demonstration. An AI application that works reliably is an engineered product.**

## 7. Final Mentor Challenge

**Mentor**: Students, I don't want you to become technology collectors. I want you to become problem solvers. Imagine a company approaches you with this requirement:

"We want an intelligent assistant that can understand our business documents, access authorized business APIs, answer customer questions, execute workflows and generate reports."

Can you build it? You should be able to:

1. Understand the business requirement.
2. Design the application architecture.
3. Select the appropriate LLM.
4. Connect organizational knowledge using RAG.
5. Integrate business systems using APIs and MCP.
6. Design controlled agentic workflows.
7. Implement security and authorization.
8. Evaluate AI responses.
9. Monitor production performance.
10. Maintain and improve the application.

That is the difference between someone who knows AI tools and someone who engineers AI systems.
