# Tokens and Embeddings — Understanding the Foundation of LLMs

Before learning RAG, MCP, AI agents, or building a chatbot, every AI engineer should understand two fundamental concepts: Tokens and Embeddings.

Think of an LLM as a student who reads language, converts it into numerical representations, and uses those representations to generate answers.

## 1. What are Tokens?

A token is a small unit of text that a language model processes. Depending on the tokenizer, a token may represent a whole word, part of a word, punctuation, or another text unit.

For example, consider this sentence:

Input sentence

"Transflower teaches AI engineering."

Illustrative tokenization

Trans

flower

&#x20;teaches

&#x20;AI

&#x20;engineering

.

Illustration only. Actual token boundaries depend on the model's tokenizer.

### Why do tokens matter?

- Input tokens: The prompt, conversation history, and supplied context.
- Output tokens: The response generated by the model.
- Context window: The maximum amount of tokenized input and output the model can handle in a request.
- Cost and latency: Many hosted LLM services calculate usage based on input and output tokens.

For English text, a rough estimate is that 1 token is about ¾ of a word, but this varies significantly by language, code, formatting, and tokenizer. Marathi and other Indian languages may tokenize differently.

### Example: LLM request

```
User prompt
    |
    v
Tokenizer
    |
    v
Token IDs: [1542, 821, 309, ...]
    |
    v
Language Model
    |
    v
Generated Token IDs
    |
    v
Detokenizer
    |
    v
Readable answer
```

The model processes token IDs, not words in exactly the way a human reads them.

## 2. What are Embeddings?

An embedding is a numerical vector representing text, an image, or another item in a space where useful relationships can be measured.

Text with similar meaning can often have embeddings that are close together, although this depends on the embedding model and the task.

For example:

- "How can I learn Java?"
- "I want to study Java programming."
- "What is the best way to learn Python?"

The first two sentences have similar meanings, so a suitable embedding model may place their vectors relatively close together.

Related sentences cluster together in vector space. The actual embedding dimensions and positions are learned by the model, not manually assigned.

An embedding might look like this in a simplified example:

```
text = "I want to learn Java"embedding = [0.12, -0.45, 0.78, 0.09, ...]
```

Real embedding vectors may contain hundreds or thousands of numerical dimensions. Each number is not usually a human-readable feature like "Java knowledge" or "programming interest."

## 3. Tokens vs. Embeddings

| Feature            | Tokens                                            | Embeddings                                        |
| ------------------ | ------------------------------------------------- | ------------------------------------------------- |
| What are they?     | Units of text processing                          | Numerical vectors                                 |
| Main purpose       | Represent input and output for an LLM             | Represent semantic or other learned relationships |
| Example            | Token IDs such as `[1542, 821]`                   | Vector such as `[0.12, -0.45, 0.78, ...]`         |
| Used for           | Text generation, context limits, token accounting | Semantic search, clustering, retrieval            |
| Common application | LLM chat completion                               | RAG and vector databases                          |

Remember: Tokens represent pieces of text; embeddings represent learned numerical relationships.

## 4. How Tokens and Embeddings work inside an LLM

Sentence

"Explain object-oriented programming"

Tokenizer

Splits text into tokens and maps them to token IDs

Token embeddings + positional information

Represent token IDs as vectors and encode sequence position

Transformer layers

Attention and neural network computations build contextual representations

Next-token prediction

The model predicts and generates the next token repeatedly

A useful distinction: LLMs typically have learned token embeddings as part of their internal architecture. In contrast, RAG applications commonly use a separate embedding model to convert document chunks and queries into vectors for retrieval.

These two types of embeddings are related concepts, but they do not necessarily use the same model or vector space.

## 5. How embeddings power RAG

Imagine a student asks the TFLCoMentor chatbot:

"What skills should I learn to become a Java backend developer?"

The system needs to find relevant learning material before asking the LLM to generate a grounded answer.

Course documents and learning roadmap

Split documents into chunks

Embedding model converts chunks into vectors

Vector database stores vectors and chunk references

Student question → Query embedding

Similarity search retrieves relevant chunks

LLM generates an answer using retrieved context

The critical point is that the database does not normally search only for identical words. It searches vector representations for relevant matches.

A common similarity measure is cosine similarity:

\\[ \operatorname{cosine}(A,B)= \frac{A\cdot B}{\\|A\\|\\|B\\|} \\]

For nonzero vectors, a higher cosine similarity often indicates greater alignment between their directions. Whether that means stronger semantic relevance depends on the embedding model and the retrieval task.

```
from sentence_transformers import SentenceTransformerfrom sklearn.metrics.pairwise import cosine_similaritymodel = SentenceTransformer("all-MiniLM-L6-v2")sentences = [    "I want to learn Java programming.",    "I want to study Java development.",    "The weather is pleasant today."]vectors = model.encode(sentences)scores = cosine_similarity(vectors)for i, sentence in enumerate(sentences):    print(f"\n{sentence}")    print("Embedding dimensions:", len(vectors[i]))print("\nSimilarity between sentence 1 and 2:",      round(float(scores[0][1]), 3))print("Similarity between sentence 1 and 3:",      round(float(scores[0][2]), 3))
```

The similarity scores are model-dependent, not probabilities or guaranteed measures of truth. The first pair would generally be expected to have greater semantic similarity than the unrelated pair.
